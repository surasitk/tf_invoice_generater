## ฟีเจอร์

### เอกสารที่ออกได้ 4 ประเภท

| เอกสาร | เลขรัน | หมายเหตุ |
|---|---|---|
| ใบเสนอราคา | `{ClientID}-Q{yymmdd}-{NNN}` | แปลงเป็นใบแจ้งหนี้ได้ในคลิกเดียว |
| ใบแจ้งหนี้ | `INV-{ClientID}-{yymmdd}-{NNN}` | VAT 7% อัตโนมัติ · ตัวอักษรภาษาไทยอัตโนมัติ |
| ใบกำกับภาษี/ใบเสร็จรับเงิน | `TAX-{ClientID}-{yymmdd}-{NNN}` | ออกจากใบแจ้งหนี้ได้ทุกสถานะ · รองรับหัก ณ ที่จ่าย 3%/7% |
| หนังสือรับรองหัก ณ ที่จ่าย (50 ทวิ) | `WHT-{yymmdd}-{NNN}` | ใช้แบบฟอร์มจริงของกรมสรรพากร · ออกได้ 2 ฉบับ |

### แท็บอื่น

- **หน้าหลัก** — ยอดขายเดือนนี้เทียบเดือนก่อน, ลูกหนี้คงค้าง, ภาษีขายเดือนนี้, ใบเสนอราคารอตอบรับ, **อายุลูกหนี้ (AR Aging)** แยก 0-30/31-60/61-90/90+ วัน, กราฟยอดขาย 12 เดือน, การ์ดลูกค้าแยกชำระแล้ว/ยังไม่ชำระ
- **ประวัติเอกสาร** — แยกเป็นหมวดตามประเภทเอกสาร พร้อมจำนวนฉบับและยอดรวมของแต่ละหมวด · ค้นหา · กรองตามสถานะและช่วงวันที่
- **รายงานภาษีขาย** — สรุปสำหรับ ภ.พ.30 · กรองช่วงวันที่ · Export CSV/Excel
- **ลูกค้า (Vendor)** — ทะเบียนลูกค้า + Client ID ที่ใช้ในเลขรันเอกสาร
- **ตั้งค่า** — ข้อมูลบริษัทผู้ออกเอกสาร, โลโก้, Slack webhook
- **ผู้ดูแลระบบ** — สร้าง/ระงับผู้ใช้ และกำหนดสิทธิ์

## กติกาสำคัญ

### 🔒 เอกสารที่ออกแล้ว "ลบไม่ได้"

ตามหลักบัญชี ระบบไม่มีปุ่มลบเอกสาร และ Firestore Security Rule ตั้ง `allow delete: if false` ไว้

**ออกเอกสารผิด ให้ทำแบบนี้แทน:**

1. ไปที่แท็บ **ประวัติเอกสาร**
2. เปลี่ยนสถานะเอกสารนั้นเป็น **"ยกเลิก"** → ระบบจะบังคับให้ระบุเหตุผล
3. ระบบบันทึกเหตุผล + ชื่อผู้ยกเลิก + วันเวลาไว้เป็นหลักฐาน
4. ออกเอกสารใหม่ตามปกติ — จะได้**เลขใหม่** ไม่ใช้เลขเดิมซ้ำ

ยอดของเอกสารที่ยกเลิกจะถูกตัดออกจาก **แดชบอร์ด · AR Aging · การ์ดลูกค้า · ยอดรวม Vendor · กราฟยอดขาย · รายงาน ภ.พ.30** ทั้งหมดโดยอัตโนมัติ

> **กรณียกเลิก "ใบเสร็จ" ที่ออกจากใบแจ้งหนี้** — ระบบจะถามว่าต้องการคืนสถานะใบแจ้งหนี้ต้นทางเป็น "ค้างชำระ" หรือไม่ ตอบ **ใช่** ถ้าจะออกใบเสร็จใหม่

### เลขที่เอกสาร

เลขรันมาจาก "เลขสูงสุดที่เคยออก + 1" ไม่ใช่ "นับจำนวนใบ + 1" จึงไม่มีทางได้เลขซ้ำแม้จะมีใบถูกยกเลิก และก่อนสร้าง PDF ทุกครั้ง ระบบจะดึงข้อมูลล่าสุดมาตรวจซ้ำอีกรอบ — กันกรณี 2 คนออกเอกสารพร้อมกัน

> ไม่แตะโครงสร้างข้อมูลและไม่แตะการสร้างไฟล์ PDF — PDF ที่ออกมายังเป็นขนาด A4 เต็มเหมือนเดิมทุกประการ (การย่อเกิดบนหน้าจอเท่านั้น)

### v1.2.0 — 1 กันยายน 2569

**เอกสารใหม่**
- ➕ **หนังสือรับรองการหักภาษี ณ ที่จ่าย (ม.50 ทวิ)** — แท็บใหม่ ออกเอกสารเดี่ยว ไม่ผูกกับใบแจ้งหนี้
  - ใช้ **ไฟล์ PDF แบบฟอร์มจริงของกรมสรรพากร** เป็นแม่แบบ แล้วเติมข้อมูลลงในช่องของมันเอง (ไม่ได้วาดเลียนแบบ) เอกสารที่ได้จึงเหมือนต้นฉบับทุกจุด
  - ประเภทเงินได้ 22 รายการ จัดกลุ่มตามมาตรา 40 / เงินปันผล 40(4)(ข) / มาตรา 3 เตรส พร้อมอัตราหักอัตโนมัติ (ค่าบริการ 3% · ค่าโฆษณา 2% · ค่าขนส่ง 1% · ค่าเช่า 5%)
  - รองรับครบ: ภ.ง.ด. 7 แบบ · กองทุน 3 ประเภท · ผู้จ่ายเงิน 4 กรณี
  - ออกได้ 1 หรือ 2 หน้า (ฉบับที่ 1 แนบยื่นภาษี / ฉบับที่ 2 เก็บหลักฐาน)
  - ไม่นับเป็นยอดขาย ไม่เข้ารายงาน ภ.พ.30 ไม่ขึ้นแดชบอร์ดลูกค้า

**Flow ออกใบเสร็จ**
- ออกใบเสร็จจากใบแจ้งหนี้ได้ **ทุกสถานะ** (เดิมได้เฉพาะ "ค้างชำระ")
- เพิ่มปุ่ม "🧾 ออกใบเสร็จ" ในแท็บประวัติเอกสาร (เดิมมีเฉพาะในแดชบอร์ด)
- dropdown อ้างอิงจัดกลุ่มตามสถานะ + ติดป้ายใบที่ออกใบเสร็จไปแล้ว
- เตือนก่อนออกซ้ำ หรือออกจากใบที่ยกเลิกไว้

**ประวัติเอกสาร**
- แยกเป็น 4 หมวดตามประเภทเอกสาร แต่ละหมวดมีจำนวนฉบับและยอดรวม
- ยกเลิกเอกสารต้องระบุเหตุผลเสมอ บันทึกผู้ยกเลิกและวันเวลา แสดงในตาราง
- ใบเสนอราคาใช้คำสถานะของตัวเอง (รอตอบรับ / ตอบรับแล้ว)

**แดชบอร์ด**
- KPI ใหม่: ยอดขายเดือนนี้เทียบเดือนก่อน · ลูกหนี้คงค้าง · ภาษีขายเดือนนี้ · ใบเสนอราคารอตอบรับ
- เพิ่ม **AR Aging** แยกอายุลูกหนี้ 0-30 / 31-60 / 61-90 / 90+ วัน พร้อมยอดค้างเกิน 60 วัน

**แก้ไขข้อผิดพลาด**
- 🔴 **รายงาน ภ.พ.30 นับ VAT ซ้ำ 2 เท่า** — เลือก "ทั้งหมด" แล้วใบแจ้งหนี้ที่ออกใบเสร็จไปแล้วถูกนับซ้ำกับใบเสร็จ
- 🔴 **ยกเลิกใบเสร็จแล้วยอดหายจากระบบ** — ใบแจ้งหนี้ต้นทางยังถูกซ่อนอยู่ ทั้งที่ยังไม่ได้รับเงิน
- 🔴 **เลขเอกสารซ้ำได้** — เดิมใช้ "นับจำนวนใบ + 1" พอมีใบถูกยกเลิกจะได้เลขเดิมซ้ำ
- 🔴 **แปลงใบเสนอราคาเป็นใบแจ้งหนี้ไม่ได้** — ส่งยอดเงินเข้าช่อง "จำนวน" ทำให้ยอดรวมเป็น 0
- 🟠 **บันทึกขึ้น Cloud ไม่สำเร็จแบบเงียบ** — ตอนนี้เตือนชัดเจนว่าเอกสารอยู่แค่ในเครื่องนี้
- 🟠 **ดึงรายการจากใบแจ้งหนี้มาออกใบเสร็จแล้วจำนวนเพี้ยน** — "10 ชิ้น × 500" กลายเป็น "1 × 5,000"

## กติกาการตั้งเลขเวอร์ชัน

| รูปแบบ | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| `X.0.0` | เปลี่ยนโครงสร้างใหญ่ · เพิ่มเอกสารประเภทใหม่ที่กระทบทั้งระบบ | 1.0.0 → 2.0.0 |
| `1.X.0` | เพิ่มฟีเจอร์ใหม่ | 1.2.0 → 1.3.0 |
| `1.2.X` | แก้ bug · ปรับข้อความ · ปรับหน้าตาเล็กน้อย | 1.2.0 → 1.2.1 |

เลขเวอร์ชันอยู่ที่ **บรรทัดบนสุดของบล็อก `<script>` แรกใน `index.html`**

```js
const APP_VERSION = "1.2.0";
const APP_VERSION_DATE = "2026-09-01";
```

แก้ที่นี่ที่เดียว แล้วเลขจะไปโผล่ที่หัวเว็บ หน้าเข้าสู่ระบบ และถูกประทับลงในเอกสารทุกฉบับที่ออก (ฟิลด์ `appVersion`) เพื่อให้ไล่ปัญหาย้อนหลังได้ว่าเอกสารใบนั้นออกด้วยเวอร์ชันไหน

## ขั้นตอนปล่อยเวอร์ชันใหม่

1. แก้ `index.html` (รวมถึง `APP_VERSION` และ `APP_VERSION_DATE`)
2. เพิ่ม Release Note ของเวอร์ชันนั้นใน `README.md`
3. อัปโหลดทั้ง 2 ไฟล์ขึ้น GitHub → เปิด Pull Request → ตรวจ → Merge เข้า `main`
4. รอ GitHub Pages build ~1 นาที
5. เปิดเว็บ กด **Cmd + Shift + R** (hard refresh) แล้ว**ตรวจว่าเลขเวอร์ชันบนหัวเว็บเปลี่ยนแล้ว** — ถ้ายังเป็นเลขเก่าแปลว่าเบราว์เซอร์ยัง cache อยู่หรือ deploy ยังไม่เสร็จ
6. *(ถ้าต้องการ)* สร้าง Release/Tag `v1.2.0` บน GitHub เพื่อให้ย้อนกลับได้ง่าย

> ⚠️ `main` ต่อกับ GitHub Pages โดยตรง — **commit ลง `main` = ขึ้นเว็บทันที** ควรผ่าน Pull Request ทุกครั้งเพื่อได้เห็นบรรทัดที่เปลี่ยนก่อน และกด Revert ได้ในคลิกเดียวถ้ามีปัญหา

## สิ่งที่ยังต้องทำ / ข้อจำกัดที่รู้อยู่

| เรื่อง | รายละเอียด |
|---|---|
| 🔴 Firestore Security Rules | คู่มือ `firebase-setup.md` เขียนไว้ว่า `allow read: if true` — ถ้ายังใช้ค่านั้นอยู่ ข้อมูลใบแจ้งหนี้ทั้งหมดอ่านได้โดยไม่ต้องเข้าสู่ระบบ **ควรตรวจและปิดให้เหลือเฉพาะผู้ที่ล็อกอิน** |
| 🔴 Slack webhook เดิมหลุด | ตัวเก่าอยู่ใน git history ของ repo สาธารณะ ต้อง revoke ใน Slack |
| 🟠 PDF เก็บใน Firestore | เก็บเป็น base64 ในเอกสาร (จำกัด ~0.9 MB/ใบ) และหน้าประวัติ/แดชบอร์ดดึงมาทั้งหมดทุกครั้งที่เปิด — พอเอกสารเยอะจะช้าและเปลืองโควตา ควรย้ายไป Firebase Storage |
| 🟠 ไม่มี backup อัตโนมัติ | ควรตั้ง export Firestore เป็นระยะ |
| 🟡 AR Aging นับจากวันที่ในเอกสาร | ระบบยังไม่มีช่องวันครบกำหนดชำระ ถ้าต้องการให้แม่นต้องเพิ่มเครดิตเทอมในใบแจ้งหนี้ก่อน |
| 🟡 ไม่มีสภาพแวดล้อมทดสอบ | มีแต่ production ควรทดสอบด้วยไฟล์ในเครื่องก่อน merge ทุกครั้ง |
